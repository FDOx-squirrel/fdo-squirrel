## fdo-squirrel v1.2.0 — tidier output folder

`--outdir` now holds the finished bundle plus the files worth opening
directly; everything else a run generates moves into a `_work/` subfolder.

- Next to `<name>-fdo-bundle.zip`: `fdo-metadata.ttl`, `ro-crate-metadata.json`,
  `rdf_modelling_report.html` and `fdo_overview.png` (the PNG only if the
  Mermaid CLI is available). All other generated files (diagrams, `FDOx.yaml`,
  the JSON report, landing page, linkset) are in `_work/`.
- The finished bundle is byte-identical to the one the previous layout
  produced: every generated file is still folded into it.
- The output folder is still cleared at the start of every run.
- Callers that read `fdo-metadata.ttl` or the bundle from the output folder
  (such as `fdo-3d-packager`) keep working; anything that read other
  generated files directly now finds them in `_work/`.
- New test `tests/test_output_layout.py`.
- `.gitignore` covers `output*/`, `out/` and a stray `fdo_overview.mermaid`
  in the repository root.
- Documentation: what Zenodo serves for Signposting (`docs/signposting.md`)
  and the `roc-validator` result (`docs/ro-crate-profile.md`).

## fdo-squirrel v1.3.0 — related resources keep their relation type

The `relation` of an MD.cff `related_resources` entry (`isDerivedFrom`,
`isReferencedBy`, ...) used to end up as a bare `dct:relation`, and the
RO-Crate did not carry it at all. A scan and a reconstruction derived from it
could therefore not be told apart from any other pair of linked objects.

- **Typed links in `fdo-metadata.ttl`.** The generic `dct:relation` stays; next
  to it the relation selects a predicate: `isDerivedFrom` gives
  `prov:wasDerivedFrom`, `isReferencedBy` gives `dct:isReferencedBy`,
  `references` gives `dct:references`, `isPartOf` gives `dct:isPartOf`,
  `hasPart` gives `dct:hasPart`. `isSupplementTo` and `isDocumentedBy` have no
  standard counterpart and stay `dct:relation` only.
- **The `note` of a related resource** is written to the TTL as a DCAT
  qualified relation (`dcat:qualifiedRelation` with `dct:relation`,
  `dcat:hadRole` and `rdfs:comment`), only for entries that have a note.
- **RO-Crate.** `isDerivedFrom`, `isPartOf` and `references` become
  `isBasedOn`, `isPartOf` and `citation` on the root entity; the target is a
  `CreativeWork` entity with its `name`, and with the `note` as `description`.
  Targets without an `http(s)` IRI are left out of the crate.
- **Fix: blank nodes.** Values without an `id` (a contributor with only a
  label, the object type) all used the same blank node `_:obj1`, so they
  became one node carrying every label. They are now one node per field and
  position.
- Output that changes for existing packages: the typed triples, the
  qualified relations, and the blank-node names. A package without
  `related_resources` changes only in the version string and in its blank
  nodes.
- New test `tests/test_related_resources.py`.
